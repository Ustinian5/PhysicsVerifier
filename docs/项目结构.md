# 项目结构

| 目录 | 职责 |
|---|---|
| `core/` | 检索、语义检查、证据定位和诊断发布 |
| `rules/`、`symbolic/` | 基础规则与可选符号核查 |
| `rule_framework/` | 规则构建、规范化与结构验证 |
| `catalogs/` | 规则库及其构建输入 |
| `scripts/` | 构建、运行和评测入口；旧实验包装器在 `legacy/` |
| `training/` | 数据准备、训练和奖励服务 |
| `evaluation/` | 基准测试及数据隔离检查 |
| `tests/` | 回归测试与小型 fixtures |
| `docs/` | 简洁的共享说明 |
| `experiments/` | Git 跟踪的实验清单 |
| `data/`、`results/` | 数据及实验原始产物，不进入 Git |
| `private_docs/` | 私人实验日志、当前计划、运维信息和必要历史归档，不进入 Git |

## 主要代码

- [run_catalog_comparison.py](../scripts/run_catalog_comparison.py)：当前主线的C4新旧库对照，同一120B会话完成检索和诊断；复用[continuous_context_v3.py](../scripts/continuous_context_v3.py)的冻结提示。
- [bounded_tree.py](../rule_framework/bounded_tree.py)：新库的逐规则Topic选择与有界分页场景归组；不调用embedding。

原分段verifier及训练接入继续保留以下模块：

- [unified_semantic_matcher.py](../core/unified_semantic_matcher.py)：背景分析和规则树导航。
- [physics_rule_verifier.py](../core/physics_rule_verifier.py)：连接检索、checker、定位与发布。
- [semantic_rule_checker.py](../core/semantic_rule_checker.py)：规则检查提示、结构化响应和证据校验。

运行入口统一见 [脚本说明](../scripts/README.md)，不在多个文件重复维护命令。

## 产物与维护

每次实验保存输入、规则库、代码、模型参数和输出的身份信息，详见 [实验清单](../experiments/README.md)。Git 只同步代码和被跟踪文件，不能代替数据、原始响应与 trace 的交付。

临时文件、失去用途的预览和重复说明及时删除。原始实验记录、冻结输入及明确要求保留的历史方案保留必要的唯一归档；移动或删除文档时同步修复引用。可恢复的旧共享文档直接通过 Git 历史追溯，不额外复制备份。
