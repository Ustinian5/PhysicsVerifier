# 效果测评

完整流程的效果看最终诊断是否正确、漏掉多少真实错误，以及是否误罚正确解答。检索和发布阶段的统计用于解释差异。

## 怎样做对照

- 固定同一批题目、候选解答以及比较因素以外的条件；比较规则库时固定在线模型、提示、工具和预算，比较提示时固定库。
- 参考答案和评价标签仅供评审，不发送给被测 verifier。
- 样本按题目和近重复题族去重；重复调用不能增加独立样本数。
- 构建规则的数据与评测题按正文和题族隔离，不能只按ID。2026-10-19已发现旧1,123叶库的3000条构建语料与开发50题有23道同题干、2道同回答，且13题来源进入19条正式规则；重标标签不会消除该重叠，细节见[规则库说明](规则库说明.md)。
- 开发题用于调试，验证题用于选方案，最终测试题用于冻结后的报告。用于修改提示、规则或阈值的题目不能再作为未见测试。
- 正确解答和错误依据需要复核，不能仅凭 reward 标签或被测模型自己的判断。
- 模型、推理配置、检索宽度、重试、缓存、symbolic 设置和发布限制随运行清单固定。

## 报告哪些指标

| 指标 | 含义 |
|---|---|
| 错误级 Precision / Recall / F1 | 正确诊断占比、真实错误被覆盖比例及二者的综合表现 |
| 正确题误报率 | 正确解答中至少收到一条错误诊断的比例 |
| 错误题有效检出率 | 错误解答中至少检出一个真实错误的比例 |
| 完成率与失败分布 | 多少题有有效结果，失败发生在哪一步 |
| 成本 | 模型请求数、token、耗时和费用 |

有效诊断须有成立的物理依据并对应真实错误，匹配时避免重复计数。现有 `evaluate_physics_eval_sets.py` 主要计算位置匹配；`evaluate_question_level_sets.py` 主要按诊断是否为空计算题目级指标。**这些自动指标不能单独证明物理判定正确**，应结合诊断复核并明确标注统计口径。

位置计分还须核对 GT 表示是否完整：引文偏移、段落位置和原解答必须对应；评审包省略段落字段时，不能默认仍与原数据计分等价。缺少可靠定位的标注单列，说明是否计入 recall 分母，不能全部解释为模型漏检。修改定位处理后对全部对照组统一重评分，保留原口径记录。

按同题配对报告差值和置信区间。所有预定样本都要交代去向；API、解析、检索和 checker 失败单列，不能把失败当作正确题未误报。共同有效子集的结果必须同时给出全量完成率和排除数量。

## 从哪里运行

| 工作 | 入口 |
|---|---|
| 构造数据并运行端到端评测 | `scripts/run_physics_eval_pipeline.py` |
| 直接运行或只运行检索 | `scripts/run_verifier.py` |
| 同模型直接检查 / Terra 规则树自主检查 | `scripts/run_llm_checker_baseline.py`（`--api-mode responses`；加 `--rule-catalog` 启用树和叶规则工具，在同一会话中直接诊断） |
| 四组检索对照 / 统一 checker 回放 | `scripts/run_retrieval_comparison.py` / `scripts/run_retrieval_checker.py` |
| 固定候选后比较 checker | `scripts/run_checker_replay.py` |
| 直接强模型与既有四组的代理指标对照 | `scripts/evaluate_direct_baseline_comparison.py`（先复现既有四组口径；`--tree-review` 比较有无规则辅助的两组 Terra） |
| 新版bench离线重评分 | `scripts/rescore_frozen_bench.py`（`prepare --scope all39`冻结E01–E39；复现旧分数后，固定终稿和算法换参考，不新增生成；首批4组保持独立归档） |
| 错误位置指标 / 题目级指标 | `scripts/evaluate_physics_eval_sets.py` / `scripts/evaluate_question_level_sets.py` |

命令参数见 [脚本入口](../scripts/README.md)。Python 使用 conda `physicsverifier`；凭据从运行环境读取。正式数据和模型可用性需由实际实验核实，旧文档中的模型名不能代替当前接口验证。

2026-10-18先完成近期4组，随后按用户要求完成全部39组重评，每组原50题，同时计算旧187条与修订201条确认错误的位置代理。原四组历史发布成绩采用共同49题，本次另提供统一全50题的新旧值；保留失败题已存部分诊断，不补造或重生成。原13项技术失败、41项强制协议不合规单列，技术失败与真实空诊断区分。

旧参考可定位130条，新参考可定位198条，须区分标签内容与定位覆盖变化。新201条含3条无错误原句的遗漏，另给198条可定位参考的敏感性结果；3条未决不作为正负金标。主Precision以可定位诊断为分母，另报告全部发布诊断及未决位置重叠诊断的敏感性结果。28项配对比较按原定对照解释，区间未校正多重比较；同一50题反复开发、看过首批结果后扩展全量，不能当作论文独立验证。

bench验收不要求分数上涨。已知错漏标案例回归与“同位置、错物理理由”的负控先行；正式重评分后按固定哈希抽取最多4条新增命中、4条丢失命中，解释内容修订、定位修复或位置误命中，程序不自动裁定物理正误。位置代理不能代替独立语义评价，个别标签修复不代表全库已准确。

首批4组的8条样例已由Codex assistant审读。10.19又审读全量报告固定抽取的8条及4条机制样例，human_gold=false；另核对全部39组、3042条诊断和1253次位置命中，逐题结果精确复现，最大匹配与零偏移修正不改变本批计数。原报告、标签和代码保持冻结，新增审读与源文件哈希关联。

已确认位置判定会接受错误物理理由、漏掉同根不同引文，并可能让同一物理根因重复诊断分别匹配不同GT。唯一定位用的扩展上下文也可能覆盖其他主张；应与核心错误区间区分。39组累计642条不可定位诊断不进入主Precision分母，必须同时保留全部发布诊断的分母敏感性结果。12条针对性审读不是全量语义评测，不据此估计真实误报率或改写分数；证据在`results/bench_rescore_20261018/all39/matching_audit.json`，沿用既有结果分发方式，不要求重新推理。

## 固定规则实验能说明什么

checker 回放可以输入真实检索结果，也可以人为指定规则。两者必须分别标记为 `semantic_retrieval` 和 `frozen_target_binding`。

指定规则实验只说明“拿到这条规则后能否检查”，不能证明检索或完整 verifier 改善。检索替换实验应继续接相同 checker 与发布流程，比较最终结果。

## 复现材料

每次保留冻结输入、规则库、运行配置、代码版本、原始响应、trace、指标及必要的复核依据。统一清单规范见 [experiments/README.md](../experiments/README.md)。

历史结果按实际模型和评价口径引用。例如，完成于 2026-09-02、飞书 9.6 同步的 100 题规则库对照使用 Qwen30B 和位置匹配；飞书 9.2 的 DeepSeek 奖励训练属于另一项实验。当前研究方向见 [项目进展](项目进展.md)。
