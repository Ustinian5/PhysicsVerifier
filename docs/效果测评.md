## 步骤级

步骤核查的最终消息可带 `CHECK` 或 `check` 格式标签。程序核对消息正常结束、正文符合原诊断结构、引用编号均来自本次实际投递的材料后，按原流程发布。第3道开发题和第43道正式题的 RAG 空诊断均从原始响应回放。[解码与回放](../scripts/step_check_format.py)

新版步骤级在本次实测组的诊断发布并冻结后，由服务器上的 GPT-OSS-120B medium 独立认定命中。每次新会话只读取题干及上下文、按原文编号的完整30B回答、一条已发布诊断和该题全部有效参考根因。四组使用相同裁判，组名、检索材料、检查轨迹和历史命中判定均从请求中移除。逐题相同的裁判输入共用一次响应，各组仍按自己的实际发布条数计数。每条首次裁决同时给出根因、纠正方向和支持该判断的连续行号，程序从冻结30B原答取回对应字符。找不到对应陈述时返回空行号；缺乏原文支持的根因判定计零命中。[当前英文裁判提示](../rule_framework/step_match_lines.py) · [服务器执行与回放](../scripts/run_step_line_judge.py)

裁判同时核对根因、纠正方向和30B原文证据。同一错误的改述或另一处表述可以命中，仅位置重合、方向相反或只指出后果的诊断不得分。每组每题的一条诊断和一个根因各最多计一次。Precision 的分母是可定位的发布诊断数，包括重复诊断。Recall 的分母是评测题中的全部有效根因，包括检查失败和零诊断题。F1 为两者的调和平均数。另列全部发布、不可定位、未决重叠、检查失败，以及以全部发布作分母的三项。裁判记录缺失或无效时保存断点和覆盖，各组先报告一次调用取得有效行段、明确找不到陈述、行号无效、声称命中但缺少行号、其他内容失败的数量。实际定位率按有效行段数除以发布条数计算。11月27日定稿，每组首次技术失败率按该组全部发布诊断计算，不超过5%即通过。技术失败包括无效行号、不可解析输出和声称命中却缺少行号。明确找不到支持原文单列，实际定位率另报。超线组保留逐条原因，等待处置；通过组按冻结公式发布。纯组已冻结99份检查和63条一轮裁决，55条取回原文、7条未找到、1条行号无效，技术失败率1.59%，通过。[验收与计分](../scripts/step_judge_release.py)

11月26日原逐字引文协议下，步骤级纯组发布63条诊断。32条首轮裁决有效，另31条因引文未通过校验获准各补一次定位。120B在隐组会话按原裁决选择连续行号，程序从30B原答取回原文。若原裁决提出同因同向命中而补裁找不到支持段落，该条记为未确定，命中计零。所有诊断仍按同一套逐题一对一规则计分。[本批次补裁与离线计分](../scripts/repair_step_judge_locations.py)

本轮直接使用旧 bench。步骤级参考来自 GPT-6.1 Sol high 对照原参考的四轮独立标注及先前冻结的引文和自我纠错复核，均为机器标注。登记100题，180个已确认根因中有16个已由学生自己纠正，另有2个未决。主表沿用99题、163个有效根因，覆盖表保留100题、164个有效根因。11月已发布的各批次成绩使用当时的离线复核；新裁判的四组结果独立发布。[步骤标注](../scripts/run_corrected_annotations.py) · [历史发布与计分](../scripts/review_aligned_step_revision.py)

## 最终答案

11月21日发布的题目级 bench 从702个保留候选核查题设、参考及30B最终回答。GPT-OSS-120B medium 在独立会话中对照原参考复核标签，分歧由助手绑定原文裁决，记录 `human_gold=false`。合格正确367道、错误237道，按原序取正确、错误各237道，共474道。本轮实际可测467道，含234份错答和233份正答。纯组直接判定。三个知识组按题共用1–3条英文查询，各自接收选中材料的全文后在原会话判定。服务器在生成最终输出时约束格式，四组每题各返回一个判定对象，结论可为正确、错误或未决。[输出约束](../rule_framework/final_output_format.py) · [题量修订与逐题绑定](../scripts/final_answer_cohort.py)

所有题目级评测统一以 **30B 的最终答案错误** 为正类。逐题对照该批冻结标签与 verifier 判定，标错判错计 TP，标对判错计 FP，标错判对计 FN，标对判对计 TN。旧工具版600题、新版474题及按题数抽取的子集均使用以下唯一一组指标。

| 指标 | 公式 | 含义 |
|---|---|---|
| Precision | TP / (TP + FP) | verifier 判错的回答中，标注为错的比例 |
| Recall | TP / (TP + FN) | 标注为错且获有效二分类判定的回答中，verifier 判错的比例 |
| F1 | 2TP / (2TP + FP + FN) | Precision 与 Recall 的调和平均 |

每组只将明确判对或判错的题计入混淆矩阵，公式分母为零时取 0。各组另列有效判定数 / 总题数、弃权数、内容失败数和“全体标错题检出率”（TP / 该批全部标错题数）。题目级报告统一运行 `python -m scripts.report_final_answer_metrics <已发布的结果 JSON>`，从 `original_binary_view` 取三项并逐项核对混淆矩阵。该入口适用于旧600题、新474题、同题改标复算和评测题数子集，每个组别和样本集只显示一组 P/R/F1。[报告入口](../scripts/report_final_answer_metrics.py) · [冻结计分实现](../scripts/audit_final_answer_metrics.py)

题目级本题参考答案对照复用冻结的查询和30B原答，两组用相同提示重新核查，实验组额外读取本题在 Combined Language 的原始 `label`。同一报告命令加 `--paired` 可从逐题记录复算 F1 差值、按题交换两组判定的双侧检验，以及按正误分层的配对 bootstrap 95% 区间。[实验与题源绑定](../scripts/run_final_exam_reference.py) · [配对计分](../scripts/score_final_exam_reference.py)

## 评测题数与结论稳定性

正式474题计分后，复用同一批四组输出。在正确、错误两类内分别按种子 `20261121` 与题号的 SHA-256 排序，各取前50、100、200、237题，组成100、200、400、474题四个嵌套子集。每档四组使用相同题目，报告原口径 P/R/F1、有效覆盖、弃权和内容失败。474题的四组统计须与正式发布逐项一致。

每个知识组比较相对纯120B的 F1 差值（百分点）。在每档固定子集内按正误分层、有放回地配对重抽10000次，给出差值的95%百分位区间。另从完整题集中按相同正误比例、不放回地抽取1000套嵌套子集，统计各档高于、持平和低于纯组的次数。最后一档包含全部样本，只有一个选题结果。
