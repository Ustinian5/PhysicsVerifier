# 增量规则流程

## 目标

新增样本只补充现有规则库，不生成平行规则库，也不直接把单题规则写成正式规则。

## 流程

```text
新增样本
→ 抽取带来源的候选规则
→ 并入候选池
→ 仅为新增或变化候选计算 embedding
→ 在受影响 Topic 内重新聚类、概括
→ 将概括结果与现有正式规则比较
→ 更新受影响 Topic 的正式规则和规则簇
→ 重建完整目录并做结构、检索回归
```

处理原则：

- 与正式规则完全相同：不新增规则，只记录已覆盖。
- 与候选完全相同：合并 `sample_ids` 和支持数量。
- 语义相近：交给 Topic 内 embedding 聚类，不用字符串规则自动合并。
- 只有一个样本支持：继续留在候选池。
- 至少两个不同样本支持同一机制：允许概括为正式规则。
- 概括结果与已有正式规则同机制：保留原 Rule ID，只补来源和支持。
- 概括结果是新机制：新增正式规则；不确定项进入人工审核，不自动覆盖。
- 当前正式目录是增量构建的权威基线；旧 Rule ID 不得静默删除，但同机制重概括项也不得与旧规则无条件叠加。任何替换、保留或新增都必须给出来源映射和人工审核记录。
- 未受影响 Topic 的规则核心内容、Rule→Cluster 映射和顺序哈希必须保持不变；Rule ID 和来源关系必须保留。

## 准备入口

```bash
python scripts/prepare_incremental_update.py \
  --new-candidates results/unified_rules_incremental/new_candidates.json
```

该命令不调用 API，也不修改当前正式库。它会：

- 合并候选并输出受影响 Topic。
- 建立 `results/unified_rules_incremental/` 隔离工作区。
- 复用当前概括和簇命名结果作为续跑起点；当前缓存尚未绑定排序后候选 ID、Prompt、模型版本和构建参数的完整指纹，这是重新启用增量发布前必须修复的阻断项。
- 在 `incremental_manifest.json` 中生成六步运行清单。

按清单依次运行后，`finalize_incremental_update.py` 会生成候选目录和审核报告。embedding 缓存只补充新增内容；未变化的概括批次和 Topic 簇命名直接复用。

最终产物不会自动覆盖 `catalogs/rules_unified_3000.json`。只有结构验证、变化范围审核和独立检索回归全部通过后，才人工替换正式目录。

验证阶段可直接接入主流程：

```bash
python scripts/run_verifier.py \
  --input data/test.json \
  --output results/test.json \
  --unified-catalog results/unified_rules_incremental/rules_unified_incremental.json \
  --unified-retrieval-mode semantic
```

## 验收

- 新候选、重复候选、正式规则已覆盖项数量守恒。
- 未受影响 Topic 的规则核心、Rule→Cluster 映射、Cluster 定义和顺序哈希不变化。
- 最终目录无重复 Rule ID、无失联规则、无非法引用。
- 每条新增正式规则必须至少包含一个新增或发生变化的候选来源；新增 Rule ID 必须进入 `incremental_validation.json` 人工审核。
- 旧 Rule ID 删除、同机制新旧规则叠加、超出 affected scope 的 Topic/Cluster 变化和超过预注册变更预算都会阻断接入。
- 本地独立样本检索无结构错误后，才上服务器跑较大实验。

2026-08-06 的深入审计发现原验收结论存在漏检：

- 16 条新增规则中只有 1 条包含任一新样本来源，其余 15 条由旧候选重新概括产生；
- generalized 输出从 609 变为 605：20 条旧输出消失、16 条新输出出现；preserve 策略又保留旧 20 条，形成未审核的单调叠加；
- 118 条旧规则更换 Scenario Cluster，涉及 11 个 Topic，其中 6 个不在声明的 affected topics；
- 旧 validator 只比较 Topic 内 Rule-ID 集合，没有比较 Rule→Cluster 分配，因此错误报告 `unexpected_changed_topics=[]`。

因此 1139 目录已被阻断，不能替换 1123 development 基线。必须先完成本页新增的来源、缓存指纹、Cluster diff 和变更预算门禁，再重新构建和评测；不能只补做 16 条规则的人工审核后直接晋升。
