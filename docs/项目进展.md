### 效果实验

- 20+20 validation：Gemini 3 Flash 构造/审计 GT，Qwen30B 同时作为 verifier 和 direct baseline。
- 共同有效 38 题上，1123 规则链题目级 F1 为 70.4%，direct baseline 为 76.6%；错误定位 F1 分别为 43.6% 和 38.1%。规则链召回更高，但 19 道正确题误报 16 道，且约慢 6.5 倍。
- 1123/4875 完整配置消融：4875 将题目级 F1 从 72.7% 降至 63.8%，错误定位 F1 从 43.8% 降至 24.5%。
- metadata-only 受控消融：FP 从 16 降至 8，但 TP 从 20 降至 9；题目级 F1 从 71.4% 降至 48.6%。当前 metadata 硬拒绝方案不可采用。

详细口径与共同有效子集见[效果测评](效果测评.md)。

## 规则库深度审计结论

### 1. 1123 库结构有效，但语义发布证据不足

- 6 个 Domain、123 个 Topic 中有 76 个 Topic 含规则；189 个 Cluster 中有 3 个空 Cluster，均位于没有规则的 `Optics / Laser Principles and Applications`。
- Topic 规则数中位数为 9，最大为 78；Cluster 规则数中位数为 5，最大为 29。粗化阶段所称“最大 12”只针对 102 个 residual bucket，不代表所有 Cluster。
- 609 条 generalized 规则在构建审计中均有至少两个样本支持；514 条 baseline 规则仍是单样本历史豁免。精简运行库没有携带 support/provenance 和 runtime metadata，运行时无法据此审计前提或来源。
- 真正进入 embedding 主簇的规则只有 343/1123；572 条仍位于 102 个 deferred residual bucket。结构上的全部可达不等于检索机会均等。
- 当前 semantic publish gate 的默认分数阈值为 0，且不验证 precondition、violation signature 或 evidence requirement。下游 release gate 主要检查 quote 可定位性和关键词/符号重合；这些条件不能证明物理违规。

### 2. 正确题误报是系统性门控问题

- 原始 1123 的 16 个正确题 FP 共 22 条诊断，涉及 19 条不同规则，不存在可通过黑名单解决的单一坏规则。
- metadata 组剩余 17 条 FP 均有 grounding，并通过了下游关键词/符号重合检查，但 Rule 发布门的题目侧前提和答案侧违规证据仍为空。通用符号 `r`、`h`、`x`、`hbar` 等造成的弱重合不是违规证明。
- 至少 3 条 FP 的解释明确承认所引推导正确或有效，随后仍发布错误，表明还缺少发布前自一致性检查。
- 结论：下一步必须改输出 schema 和确定性发布条件，而不是针对 validation 样本修改规则或继续补 Prompt。

### 3. 1139 增量候选未通过治理审计

- 8 条新错解产生 9 条候选和 16 条新增规则，但只有 1 条新增规则含任一新样本来源；其余 15 条主要由旧样本重新概括产生。
- 与 1123 基线比较，有 118 条旧规则更换 Scenario Cluster，涉及 11 个 Topic，其中 6 个不在声明的 affected topics。
- 历史 `incremental_validation.json` 只比较每个 Topic 的 Rule-ID 集合，没有比较 Cluster 归属，因此错误报告 `unexpected_changed_topics=[]`。
- 历史 manifest 记录的基线 SHA-256 为 `0a299a…`，当前 1123 基线为 `838506…`，原始基线文件已不存在；该候选同时属于 stale、不可复现产物。
- P1 受控回放使用当前 1123 基线重建后，16 条新增 Rule 的蓝图覆盖审计通过，旧规则 Cluster/Rule Group 迁移均为 0、unexpected Topic 为 0，但仍被五类门禁拒绝：新增正式规则 16 超过预注册预算 9，generalized 新增 16、删除 20、修改 12，新增规则本轮来源覆盖仅 1/16。
- 因此 1139 只能保留为审计产物；结构漂移被消除不等于来源和概括变化合格。

完整规则库结构、分布和维护边界见[规则库说明](规则库说明.md)。

## 唯一主线任务

实现一个结构化、可机检的双证据 precision gate，同时保持 1123 的高召回检索路径：

1. `applicability`：只能引用 `question/context`，证明规则前提在题目中成立；
2. `violation`：只能引用 `prediction`，证明答案中的具体陈述违反该规则；
3. 两段证据都必须可定位，且 Checker 解释不得同时承认推导正确；否则不发布诊断；
4. metadata 只参与检索排序和证据提示，不单独作为硬拒绝条件。

### P2：开发双证据门控

### P3：规则级合成门禁与独立 development

- 按固定 seed 从 6 个 Domain 分层抽取至少 60 条规则，覆盖 `gen_`/`exp_`、有无 symbolic primitive 和宽/窄 trigger；每条构造 5 类机制样本：真实违规、前提成立但解答正确、仅符号重合但不适用、等价公式/替代解法、信息不足或已自我修正，总量不少于 300。
- 规则级合成门禁使用 Checker-only replay；先以小批量本机 smoke 验证，再在服务器运行完整集。
- 另建 30 道错题 + 30 道正确题的独立 development 集，每个候选完整端到端重复 3 次，测量 Qwen 非确定性。
- 按归一化题目文本排除所有规则构造样本、5+5 pilot 和 20+20 validation；GT 仍用 Gemini 3 Flash，Verifier 仍用 Qwen30B。
- 固定四个受控阶段：原始 1123；显式 `applicable + violation_proven`；再加自一致性检查；最后仅将 metadata 用于排序。development 同时保留 direct baseline。

候选必须同时满足以下预注册门槛：

- 合成集结构化输出率 ≥ 99%、违规 Recall ≥ 90%、正确/不适用 FPR ≤ 5%、自相矛盾诊断为 0、三次发布决策一致率 ≥ 95%；
- 30+30 development 每次错题 Recall ≥ 90%、正确题 Specificity ≥ 70%；
- 相对原始 1123，错误定位 Recall 下降不超过 5 个百分点，错误定位 Precision 提高至少 10 个百分点；
- 三次题目级决策一致率 ≥ 90%，semantic/parse failure 必须单列。

任一门槛失败即否决，不用 20+20 validation 调参补救。

### P4：冻结、全新 validation 与 final test

- 候选通过 development 后初步冻结代码、Prompt、catalog、模型与参数。旧 20+20 只作历史回归，不参与选择或调参。
- 抽取全新 50 错 + 50 对 validation，执行一次 go/no-go：Coverage ≥ 98%、Recall ≥ 90%、Specificity ≥ 60%、题目级 F1 不低于同批 direct baseline、定位 F1 至少高 5 个百分点、自相矛盾诊断为 0。任一失败即否决；若据此修改，整套 validation 降级为 development 并重新抽取。
- 通过后再抽取全新 final test，建议 100 道错题 + 100 道经 Gemini 审计的正确题；在服务器 `tmux` 中运行冻结的胜出方案与 direct baseline。
- 报告题目级、错误定位级、coverage、失败阶段、耗时和配对置信区间；final test 若触发修改，整套样本作废并重抽。
