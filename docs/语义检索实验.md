# 语义检索实验

## 实验目的

使用六条典型样本检查背景信息驱动的 API 语义树是否能够稳定完成：

```text
BackgroundAnalysis → Domain → Topic → Scenario Cluster → Rule
```

这些样本用于观察逐层检索路径和结构问题，不用于计算总体召回率或 FP，也不要求命中固定 `rule_id`。

最新逐层输出保存在 `results/unified_rules_3000/top_down_runtime_eval_navigation_fixed.json`。

## 运行结论

- 六条样本全部运行到 Rule 阶段。
- 结构化输出错误为 0，没有发生无法读取结果的 API 中断。
- 四条样本检索到规则，两条样本正常返回空规则。
- 确认失败后能够继续进行一次有界树内回退，不会被错误临时候选截断。
- 当前结果只证明语义检索流程已经能够稳定运行，不代表规则选择最优。

## 已有全流程结果

项目已有一组 8 条样本的全流程运行结果：

- 8 条均完成 Topic、Cluster 和 Rule 检索。
- 语义结构错误为 0。
- 共检索 23 条规则，平均每题 2.875 条。
- 7 条样本产生最终诊断。

该结果可以证明完整 verifier 能够运行，但样本没有目标规则标注，因此不能据此计算真实的规则召回率和 FP。

## 当前问题

- `154795` 缺少图中几何信息，不能靠 prediction 补全。
- `194394` 缺少角向度规分量与周长的正式规则。
- 六条样本只能验证路径和结构，不能计算总体召回率或 FP。

## 后续方向

测评用于判断问题主要发生在 Topic、Cluster、Rule 检索还是下游 Checker，不根据六条样本逐条添加或修改规则。

后续规则库研究包括：

1. 使用独立样本继续评估导航、规则覆盖和最终确认。
2. 通过增量工作区补充新候选，未达到多样本支持的规则继续留在候选池。
3. 新目录通过变化范围审核和检索回归后再人工发布。

整体原则是：测评负责定位问题，规则库优化依据统一的粗粒度和动态扩展原则进行，不针对少量典型样本过拟合。

## 独立效果验证

六条典型样本和 8 条历史全流程样本只用于路径与结构验收。2026-07-30 至 31 已另行完成与这些样本隔离的 20+20 validation，并加入同模型无规则基线、错误定位 GT、coverage 和结构化失败统计。

该验证使用 `catalogs/rules_unified_3000.json` 的 1123 条粗化库；它不代表 4875 条 `rules_unified_3000_runtime_backfilled.json` 的效果。完整数据隔离协议、复现命令和结果见[效果测评](效果测评.md)。
