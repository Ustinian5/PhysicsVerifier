任务
通读题目和学生的完整解答，核查推导和最终答案。对每个能在原文定位的独立错误，指出哪一步错了、为什么错，并给出正确关系及其成立条件。接受符合题意的等价解法。结合后文辨认已经纠正的试算，同一根因及其连锁后果合记一次。依据不足时，说明哪个判断缺少什么条件。

从已确认的错误中提炼可用于其他题的检查规则。每条规则写清何时适用、应满足什么关系、怎样据此判错。即使某个错误不适合推广，也保留在核查结果中。从给定目录中选出本题所属的主题。

输出格式
只返回一个 JSON 对象，结构见下方示例。没有对应条目时用空数组。

topic_key 取输入目录中的 T 编号。错误按 E1、E2 依次编号，行号取能定位错误的最小连续范围。type 和 error_type 各选 concept、logic、calculation、modeling、units 中的一项。
status 在有确认错误时填 error_found，只有未决项时填 uncertain，两者都没有时填 no_error_found。
最多提炼 max_rules_per_sample 条规则。rule_status 用 included、not_generalizable、uncertain、rule_budget 分别表示已提炼、不适合推广、适用性未定、达到条数上限。每条规则引用至少一个来源错误。所有 source_error_ids 合起来恰好覆盖本题标为 included 的错误。symbolic_hint 取示例中的固定值。

  "topic_key": "T1",
  "semantic_audit": {
    "status": "error_found",
    "summary": "简要核查结论",
    "key_errors": [
      {"id": "E1", "type": "modeling", "message": "原解答中的具体错误",
       "correction": "正确关系及其依据", "line_start": 1, "line_end": 1,
       "rule_status": "included", "reason": "该错误用于或未用于提炼的原因"}
    ],
    "uncertain": [{"scope": "无法判定的部分", "reason": "所缺条件"}]
  },
  "experience_rules": [
    {"source_error_ids": ["E1"], "title": "规则名称", "trigger": "适用条件",
     "check_logic": "应满足的关系、检查方法和判错依据", "error_type": "modeling",
     "symbolic_hint": {"primitive": "none", "canonical": "", "required_symbols": []},
     "auxiliary": {"node_summary": "场景摘要", "scene_cues": [], "boundary_cues": [], "explore_cues": []}}
  ]
}
